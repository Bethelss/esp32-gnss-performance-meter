# GNSS Performance Meter — Android prototype

Это первая версия приложения для будущего автомобильного GNSS-прибора. Сейчас оно работает полностью автономно: вместо ESP32 использует встроенный симулятор. Поэтому его можно запускать и изучать без платы, GNSS, ICM-42688 и BLE.

## Что такое Gradle

Gradle — это программа-сборщик проекта. Она сама по себе не является частью приложения и не запускается на телефоне. Её задача — подготовить приложение:

1. прочитать настройки проекта;
2. скачать нужные библиотеки Compose, Room и AndroidX;
3. скомпилировать Kotlin-код;
4. обработать ресурсы и манифест;
5. собрать устанавливаемый файл APK;
6. запустить тесты.

`gradlew.bat` — командный файл, который запускает Gradle на Windows. `gradle-wrapper.jar` и файл в `gradle/wrapper/` фиксируют версию Gradle, чтобы Android Studio и другие компьютеры использовали одинаковую сборочную систему.

Для работы Gradle нужны два инструмента:

- JDK — Java Development Kit, программа, на которой работает Gradle и компиляторы;
- Android SDK — набор инструментов и описаний Android, из которых собирается приложение.

Android Studio объединяет редактор, Gradle, SDK, эмулятор и отладчик в одном окне. В настройках проекта Gradle должен использовать встроенный JDK Android Studio версии 17 или выше: **File → Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**.

## Как данные проходят через приложение

Сейчас поток выглядит так:

```text
SimulatorDataSource
        ↓
TelemetryRepository
        ├── главный экран и круг G
        ├── диагностика
        └── запись образцов в Room
                         ↓
                 история и графики
```

Позже `SimulatorDataSource` можно будет заменить на BLE-источник. Экраны и база при этом останутся прежними.

Каждый образец телеметрии содержит время источника, скорость, три компоненты перегрузки, состояние GNSS, спутники, sequence и признаки валидности IMU. В симуляторе эти значения искусственные, но структура повторяет будущую реальную телеметрию.

## Что находится в каталогах

```text
android-app/
├── settings.gradle.kts       список модулей проекта
├── build.gradle.kts          общие плагины сборки
├── gradle/libs.versions.toml версии библиотек
├── app/build.gradle.kts      настройки Android-приложения
└── app/src/
    ├── main/                 код приложения и ресурсы
    ├── test/                 быстрые unit-тесты без телефона
    └── androidTest/          тесты для Android/эмулятора
```

В исходном коде:

- `domain/Telemetry.kt` — общие модели данных и интерфейс источника;
- `data/SimulatorDataSource.kt` — сценарии синтетической поездки;
- `data/ReplayDataSource.kt` — воспроизведение сохранённой сессии;
- `data/TelemetryRepository.kt` — связывает источник, запись, статистику и Room;
- `storage/` — таблицы, DAO и база Room;
- `ui/Screens.kt` — экраны приложения;
- `ui/TelemetryVisuals.kt` — круг перегрузок и графики;
- `ui/MainViewModel.kt` — состояние экранов и команды пользователя;
- `recording/RecordingService.kt` — foreground-сервис, который продолжает запись при пересоздании Activity;
- `MainActivity.kt` — точка входа и навигация.

## Что можно попробовать в приложении

На экране «Прибор» выберите сценарий:

- «Покой» — почти нулевые значения;
- «Разгон» и «Торможение» — продольная перегрузка;
- «Поворот» — боковая перегрузка;
- «Манёвр» — значения могут выйти за пределы круга 1 g;
- «Потеря GNSS» — IMU продолжает работать, а GNSS становится stale;
- «Разрыв потока» — появляются пропуски sequence.

Кнопка «Начать запись» сохраняет образцы в локальную базу телефона. После остановки сессия появляется в разделе «Поездки». Там доступны графики, перемотка, воспроизведение и экспорт CSV.

## Запуск через Android Studio

1. Установите Android Studio.
2. Откройте каталог `android-app`.
3. Дождитесь `Gradle Sync`.
4. Откройте **Tools → Device Manager** и создайте виртуальный телефон с Android 8 или новее.
5. Запустите виртуальный телефон кнопкой ▶.
6. В верхней панели Android Studio выберите этот телефон и нажмите **Run**.

Если Android Studio сообщает, что не найден Java 17, выберите встроенный JDK Android Studio в настройках Gradle или установите JDK 17 через кнопку **Download JDK**.

## Запуск из терминала

Из PowerShell в каталоге `android-app`:

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

Первая команда запускает unit-тесты. Вторая собирает APK. Третья запускает Android-тесты на работающем эмуляторе или подключённом телефоне.

APK появится здесь:

```text
app/build/outputs/apk/debug/app-debug.apk
```

## Что пока не реализовано

В проекте пока нет BLE, настоящей обработки ICM-42688, связи с ESP32, управления TFT, пищалкой или энкодером. Нет также замеров 0–100 и других гоночных режимов. Это сделано намеренно: сначала проверяется интерфейс, запись и графики на воспроизводимых данных.

Foreground-сервис использует уведомление только во время записи. Bluetooth-разрешений и BLE-сканирования в текущей версии нет.

## Проверки

На текущем проекте успешно выполняются:

- `testDebugUnitTest` — 5 unit-тестов симулятора, статистики и прореживания графиков;
- `assembleDebug` — сборка устанавливаемого APK;
- `assembleDebugAndroidTest` — компиляция Android-тестов;
- `lintDebug` — 0 ошибок Lint.

Android-тесты требуют запущенный эмулятор, поэтому их компиляция и их фактический запуск — разные операции.

## Быстрая работа над главным экраном

Для подбора внешнего вида без Gradle и эмулятора есть автономный стенд:

```text
design-lab/dashboard-lab.html
```

Откройте этот файл двойным щелчком в обычном браузере. Устанавливать Node.js или запускать локальный сервер не нужно. После изменения HTML сохраните файл и обновите страницу клавишей `F5`.

В стенде можно:

- менять размер виртуального телефона, акцент, плотность и шрифт;
- управлять скоростью, спутниками и обеими компонентами G;
- перетаскивать точку в круге мышью;
- запускать сценарии разгона, торможения, поворота, манёвра, потери GNSS и разрыва потока;
- включать состояние записи.

Стенд нужен только для выбора дизайна и не попадает в APK. После утверждения варианта его размеры и цвета переносятся в Compose.

Для проверки уже перенесённого интерфейса без запуска эмулятора откройте файл `LiveDashboardPreviews.kt` в Android Studio и выберите вкладку **Split** или **Design**. Preview содержит состояния покоя, торможения, поворота, выхода за 1 g, потери GNSS, разрыва потока, записи, светлой темы и увеличенного шрифта. В Preview с названием `Interactive — 360 dp` кнопки сценариев и записи работают в интерактивном режиме.

Для последних мелких изменений на эмуляторе можно включить **File → Settings → Editor → Live Edit → Automatic**. Live Edit подходит для цветов, отступов и тела существующих composable-функций; после изменения сигнатур и добавления новых функций приложение потребуется запустить заново.
